# 관리자 사용법

[문서 목록](README.md) · [상태 복구 규칙](transaction-lifecycle.md)

## 연결하기

[관리자 페이지](https://alex311-snu.github.io/one-art/admin/)에서 다음 값을 입력합니다.

| 입력 항목 | 이 프로젝트의 값 |
|---|---|
| 저장소 소유자 | `alex311-snu` |
| 저장소 이름 | `one-art` |
| 브랜치 | `main` |
| GitHub 토큰 | 해당 저장소에 쓰기 권한이 있는 개인 토큰 |

로그인 화면의 **토큰 발급 방법**을 참고합니다. 현재 앱은 GitHub API로 파일을 저장하며, 토큰에 `Contents: Read and write` 권한이 필요합니다. 연결 정보는 사용 중인 브라우저의 로컬 저장소에 보관됩니다. 토큰을 문서나 저장소 파일에 적지 않습니다.

로컬 개발 서버에서는 GitHub 연결 대신 로컬 테스트 모드로 열립니다. 이 모드의 저장은 실제 로컬 파일을 수정합니다.

## 작품 등록·수정

1. 작가가 등록되어 있지 않으면 작가 탭에서 먼저 추가합니다.
2. **작품 추가**에서 제목, 작가, 제작연도, 재료, 크기, 사진과 작품 이야기를 입력합니다.
3. 판매 정보, 작가 승인, 전시·소유 이력을 확인합니다.
4. **미리보기**로 내용을 확인한 뒤 **저장**합니다. 편집 화면에서는 `Ctrl+S`도 사용할 수 있습니다.
5. 관람객에게 보여줄 때 **공개**를 켭니다. 공개 설정은 페이지 표시 여부이며, 데이터 파일을 비공개로 만드는 기능은 아닙니다.

미리보기에는 아직 저장되지 않은 정보가 포함될 수 있습니다. 저장 후 실제 공개 주소에서도 확인합니다. 이미 NFC·QR에 사용한 작품번호는 유지합니다.

## 예약 → 판매 → 전달

| 업무 | 목록에서 할 일 | 결과 |
|---|---|---|
| 예약 접수 | 상태를 **예약 중**으로 변경 | 예약 기록 저장 |
| 예약 취소 | **예약 취소** 클릭 | 판매 가능으로 복구, 취소 기록 저장 |
| 판매 완료 | 상태를 **소장됨**으로 변경 | 소장 시점·소유 이력 처리, 판매 완료 기록 저장 |
| 작품 전달 | **전달 완료** 클릭 후 확인 | 오늘 날짜로 전달 완료 기록 |
| 판매 취소 | **판매 취소** 클릭 후 확인 | 판매 가능으로 복구, 소유 이력 복구, 전달 상태 초기화 |

목록의 상태 변경과 버튼 처리는 바로 저장됩니다. 작품 수정 화면에서 바꾼 상태와 날짜는 **저장**해야 반영됩니다. 관리자의 **판매 가능**은 관람객 화면에서 **소장 가능**으로 표시됩니다.

판매 완료와 전달 완료는 별개입니다. 판매 완료 처리만으로 전달이 완료되지는 않습니다. 입금·환불·택배 추적은 이 앱에서 처리하지 않습니다.

## 전달일 수정과 처리 이력

작품의 **수정 → 판매 → 전달 완료일**에서 실제 전달 날짜를 지정합니다. 날짜를 비우고 저장하면 전달 완료가 취소되고, 그 사실도 처리 이력에 남습니다.

**수정 → 처리 이력**에서는 예약, 판매, 취소, 전달과 날짜 정정 기록을 최신순으로 확인합니다. **작품 기록 → 소유 이력**은 소장자와 소장 기간을 나타내는 별도 정보입니다. 공개 작품 페이지의 작품 기록에도 소유 이력이 표시됩니다.

처리 이력 화면은 기능 도입 이후 저장한 변경부터 기록합니다. 이전 거래의 세부 변경은 관리자 상단 **변경 기록**에서 GitHub 커밋을 확인합니다.

## NFC·QR 전달 확인

작품 수정 화면의 **NFC · QR**에서 주소를 복사합니다. NFC 주소는 `src=nfc`, 전시용 QR 주소는 `src=qr`를 사용하며 같은 작품을 가리킵니다.

전달 전 휴대폰으로 실제 태그를 읽어 작품번호·제목·작가·소유 이력이 맞는지 확인합니다. 태그를 읽는 행위는 소유권 변경이나 전달 완료 처리로 기록되지 않습니다. 실제 전달 후 관리자가 완료 처리합니다.

구매자 실명·연락처·입금 정보는 별도 판매 원장에서 관리합니다. 소유 이력과 처리 이력 데이터도 공개 저장소에 저장됩니다.
