# 거래 상태와 복구 규칙

[문서 목록](README.md) · [관리자 사용법](admin-guide.md)

상태 처리의 기준 코드는 [lifecycle.js](../assets/js/lifecycle.js)입니다. 관리자 목록과 작품 수정 저장은 모두 `ONELifecycle.reconcile(original, draft)`를 사용합니다.

## 상태와 화면 표시

| 저장 값 | 관리자 | 관람객 | 의미 |
|---|---|---|---|
| `available` | 판매 가능 | 소장 가능 | 구매 문의를 받을 수 있는 작품 |
| `reserved` | 예약 중 | 예약 중 | 예약 진행 중 |
| `sold` | 소장됨 | 소장됨 | 판매 완료 처리된 작품 |
| `nfs` | 비매품 | 비매품 | 판매 대상이 아닌 작품 |

`deliveredAt`은 판매 상태와 별도입니다. `sold`인 작품에서만 전달 완료일을 유지합니다. 공개 여부는 `published`로 따로 관리합니다.

## 판매 완료

`sold`로 전환할 때 거래 전 `provenance`, `soldAt`, `showSoldPrice`를 `saleSnapshot`에 보관합니다. 소장 시점을 채우고, 소유 이력을 직접 추가하지 않았다면 기본 소장자 기록을 추가합니다. 수정 화면에서 입력한 소유 이력이 있으면 이를 사용하며 불필요한 기본 기록을 중복 추가하지 않습니다.

이때 `sale_completed` 기록이 생깁니다. 상태를 그대로 두고 일반 정보만 수정하면 판매 완료 기록이 중복 생성되지 않습니다.

## 취소와 복구

**예약 취소 버튼**은 `available`로 돌리고 `reservation_cancelled`를 기록합니다. 예약 중 상태에서 비매품 등으로 변경하는 경우에도 예약 취소 기록이 남습니다.

**판매 취소 버튼**은 `available`로 돌립니다. `sold`에서 다른 상태로 변경해 저장하는 것도 판매 취소로 처리됩니다.

새 기능으로 판매 처리한 작품은 다음과 같이 복구합니다.

1. 판매 취소 전 확인 창을 표시합니다.
2. 거래 직전 스냅샷의 소유 이력·최초 소장 시점·가격 공개 설정을 복구합니다.
3. 전달 완료일과 현재 거래 스냅샷을 초기화합니다.
4. 기존 처리 기록을 유지하고 `sale_cancelled`를 추가합니다. 취소 전 전달일이 있으면 함께 기록합니다.

작품 제목·사진·가격 등 다른 정보 전체를 과거로 되돌리는 기능은 아닙니다. 판매 이후 편집한 소유 이력도 취소 시에는 거래 전 스냅샷으로 돌아갑니다.

### 기능 도입 전에 판매된 작품

이전 작품에는 `saleSnapshot`이 없을 수 있습니다. 이 경우 확인 창에 동의하면 마지막 소유 이력 한 건을 제거하고, 남은 첫 이력의 시작 월을 소장 시점으로 사용합니다. 남은 이력이 없으면 소장 시점을 비우며, 판매가 공개 설정도 끕니다.

마지막 기록이 취소할 거래인지 반드시 확인합니다. 일치하지 않으면 확인 창에서 취소하고 소유 이력을 먼저 검토합니다. 앱은 과거 거래와 소유 이력의 연결을 추정해 복원할 수 없습니다.

## 전달과 날짜 정정

- 목록의 **전달 완료**는 오늘 날짜를 기록합니다.
- 수정 화면에서 전달일을 바꾸면 이전 날짜와 새 날짜를 기록합니다.
- 전달일을 비우면 `delivery_cancelled`를 기록합니다.
- 동일한 날짜로 다시 저장해도 전달 기록을 중복 생성하지 않습니다.
- 판매 취소는 전달 완료일도 초기화합니다. 이전 전달 정보는 판매 취소 기록에서 확인합니다.

## 처리 이력의 범위

| 이벤트 | 의미 |
|---|---|
| `reserved` | 예약 시작 |
| `reservation_cancelled` | 예약 취소 |
| `sale_completed` | 판매 완료 |
| `sale_cancelled` | 판매 취소 |
| `delivered` | 전달 완료 또는 전달일 수정 |
| `delivery_cancelled` | 전달 완료 취소 |
| `status_changed` | 그 밖의 상태 변경 |

기록은 상태·시각·관련 날짜를 저장합니다. 담당자 이름, 예약 만료, 결제 내역, 취소 사유, 배송 추적은 구현되어 있지 않습니다. 처리 이력은 일반 JSON 데이터이며 변경 불가능한 감사 로그는 아닙니다. 저장소 편집 권한이 있는 사람은 데이터를 수정할 수 있습니다.

관리자 저장 실패 시 화면의 저장된 카탈로그를 새 값으로 교체하지 않습니다. GitHub 모드는 다른 사람이 먼저 수정한 데이터를 감지하면 덮어쓰기 대신 충돌 오류를 표시합니다.
