# 문제 해결

[문서 목록](README.md) · [개발·배포](development.md)

## 관람 페이지에 예전 문구가 보임

1. `/admin/`이 아닌 작품 상세 `/a/?id=작품번호`를 보고 있는지 확인합니다. 관리자에는 **판매 가능**, 공개 화면에는 **소장 가능**으로 표시합니다.
2. PC에서는 `Ctrl+Shift+R`로 새로고침합니다. 휴대폰에서는 페이지를 다시 열거나 사이트 캐시를 비운 뒤 확인합니다.
3. 배포한 커밋의 GitHub Actions가 성공했는지 확인합니다.
4. 개발자는 HTML의 스크립트·스타일 버전값을 변경했는지 확인합니다. 페이지 주소에만 새 쿼리를 붙여도 하위 스크립트의 캐시까지 반드시 갱신되는 것은 아닙니다.

## 저장했는데 공개 화면은 그대로임

관리자 저장은 GitHub 커밋 완료를 의미합니다. 공개 사이트에는 Pages 배포가 끝난 뒤 반영됩니다. 로컬 테스트 모드로 저장했다면 파일은 내 컴퓨터에만 바뀌었으므로 GitHub 업로드가 필요합니다.

저장소·브랜치가 `alex311-snu/one-art`, `main`인지 확인하고, 실제 작품의 공개 여부와 작품번호도 확인합니다.

## 다른 사람이 먼저 수정했다는 오류

카탈로그가 불러온 시점 이후 변경되어 덮어쓰기를 막은 상태입니다. 작성 중인 내용을 먼저 별도로 정리한 뒤 최신 데이터를 불러오고 수정 사항을 다시 적용합니다. 오류창의 최신 데이터 불러오기에 동의하면 작성 중인 내용은 사라집니다.

## 토큰 또는 저장소 접근 오류

저장소 이름, 브랜치, 토큰 만료와 쓰기 권한을 확인합니다. 팀원 계정은 해당 저장소 접근 권한도 필요합니다. 토큰은 관리자 연결 화면에만 입력하고 이슈·문서·스크린샷에 노출하지 않습니다.

## 판매 취소 뒤 소유 이력이 예상과 다름

새 기능으로 판매 완료한 작품은 판매 직전 스냅샷으로 복구됩니다. 판매 이후 수동 편집한 소유 이력도 함께 되돌아갑니다.

기존 판매 작품처럼 스냅샷이 없으면 마지막 소유 이력 한 건을 취소하는 방식입니다. 이전 소장자가 남아 있다면 정상일 수 있습니다. 작품 수정의 소유 이력과 GitHub 변경 기록을 비교한 후 공개해도 되는 올바른 기록으로 정정합니다. 전체 카탈로그를 과거 버전으로 덮어쓰면 다른 작품 변경도 사라질 수 있으므로 필요한 작품·필드만 검토합니다.

## 전달 완료 버튼이 보이지 않음

판매 상태가 **소장됨**이고 아직 전달일이 없는 작품에서 표시됩니다. 이미 전달 완료된 작품은 완료일이 보입니다. 날짜 정정이나 완료 취소는 **작품 수정 → 판매 → 전달 완료일**에서 처리합니다.

## 처리 이력이 비어 있음

기능 도입 이후 기록할 상태 변경이 없으면 비어 있을 수 있습니다. 예전 소유 이력은 **작품 기록**에서, 과거 파일 변경은 GitHub **변경 기록**에서 확인합니다. NFC를 읽거나 작품 페이지를 방문하는 행위는 처리 이력으로 기록하지 않습니다.

## 작품 페이지를 찾을 수 없음

주소의 `id`가 카탈로그의 작품번호와 일치하는지, 작품이 삭제되지는 않았는지 확인합니다. 비공개 작품은 준비 중 안내가 표시됩니다. 이미 태그를 전달한 작품은 삭제보다 공개 설정·상태 관리를 사용해 주소를 유지합니다.

## 로컬 관리자 저장이 동작하지 않음

`python dev_server.py`로 실행했는지 확인합니다. 단순 정적 서버에는 이 프로젝트의 저장 API가 없습니다. 로컬 저장은 서버를 실행한 컴퓨터의 `localhost`에서 확인합니다. 같은 네트워크의 다른 기기는 관람 화면을 확인하는 데 사용합니다.
